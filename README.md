# 06-shiftboard（交班台）

交班台 — 班次责任与在途批次交接：班次登记 → 在途批次归属 → 交班互斥办理 → 交班前后对账 → 错交补偿回拨。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓贴源/明细/汇总分层。  
**也不是** OA 考勤排班后台、电商订单、报表 CSV 看板。

## 启动

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=%CD%\data
set FIXTURES_DIR=%CD%\..\fixtures
uvicorn app.main:app --host 127.0.0.1 --port 10600

# 前端
cd frontend
npm install
npm run dev
```

| 接口 | http://127.0.0.1:10600 |

## 主链

登记班次与值班人 → 在途批次归属当前班次 → 发起交班（全仓同时仅一单进行中）→ 完成交班整批过户 → 交班对账报告与清单/批次同源 → 错交时对已完成交班单开补偿回拨（指定业务键整单回拨）
 
## 补偿回拨

- **单据隔离**：`compensations` + `compensation_items` 独立于正向交班表；`reconcile_reports.doc_type` 区分 `正向交班` / `补偿回拨`。
- **全局互斥**：进行中的补偿与任何正向交班不能并存，冲突由后端返回 409 并写明对端单号（`交班单#id` / `补偿单#id`），前端禁用只是辅助。
- **整单原子**：回拨 + 补偿单状态 + 对账报告在同一个 `BEGIN IMMEDIATE` 事务内；任一步失败整单回滚，补偿单落 `失败` 并写明原因，不会出现部分键已回拨。
- **禁止绕过**：系统不提供手工改 `batches.owner_shift_id` 的接口，归属只能由正向交班完成或补偿回拨完成写入。
- **同源对账**：补偿报告的前后计数与清单都由 `compensation_items` 同一批 `batch_id` 计算，可逐键追溯。

页面文案全部中文；入口：总览 / 班次 / 在途批次 / 交班办理 / 补偿回拨 / 交班记录 / 交班对账。
